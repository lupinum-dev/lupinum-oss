Use pnpm for Lupinum workspaces. Commit the lockfile. Pin the package manager in
`packageManager`.

pnpm 11 requires Node.js 22 or later. A library can still test support for
Node.js 20. In that test lane, use the standalone mode of
`pnpm/action-setup`. This runs pnpm with a supported runtime while the package
itself runs on Node.js 20. Do not pin an older pnpm version because it can
silently ignore current workspace security settings.

## Quarantine new releases

Set these values in `pnpm-workspace.yaml`:

```yaml
minimumReleaseAge: 1440
minimumReleaseAgeStrict: true
minimumReleaseAgeIgnoreMissingTime: false
```

The 24-hour quarantine reduces exposure to a compromised dependency version
immediately after publication. It does not delay changes to our own code.

Do not bypass the quarantine for convenience. A critical fix can use one exact,
reviewed exception when no safe older version works. Record the package,
version, reason, owner, and removal time. Remove the exception after the time
expires. `pnpm verify` must fail when an exception has expired.

An exact Lupinum prerelease can use a temporary first-party exception when a
fleet migration requires it. Apply the same record and removal rule.

Store the reason, owner, and UTC removal time in an inline JSON comment on the
actual install exclusion. Use a removal time within 24 hours. For example:

```yaml
minimumReleaseAgeExclude:
  - '@lupinum/example@1.2.3' # {"reason":"Urgent reviewed fix", "owner":"mat4m0", "expires":"2026-09-06T18:00:00Z"}
```

Replace the example values with the reviewed exception. Run
`pnpm check:dependencies` to check the parsed install configuration. Remove the
entry and its comment after expiry. The checker is maintained in
`starters/_shared/check-dependency-policy.mjs` and copied with `pnpm shared:sync`.
Generated repositories own their copies and need no handbook runtime dependency.
CI checks expiry daily without running a full build on that schedule.

If a script generates another install configuration, run the same checker before
its install: `node scripts/check-dependency-policy.mjs path/to/pnpm-workspace.yaml`.
Checking only the root configuration does not cover generated fixture installs.

## Update dependencies

Use Renovate for routine update pull requests. Use Dependabot alerts for known
security problems. Do not use two bots to open the same routine upgrades.
Set Renovate `minimumReleaseAge` to `1 day`. This matches pnpm's mandatory
24-hour install quarantine. Do not add a second three-day or repository-specific
delay because it makes fleet update timing difficult to understand.

Review release notes for major updates and for tools that run during install,
build, test, or publication. Run the full repository verification after a
lockfile change.

## Audit all deployable code

`pnpm audit:all` must cover public packages, the documentation app, examples,
and other deployable workspaces. A production-package audit is an additional
check. It is not a substitute for the full audit.

Pin Changelogen to the approved exact version. Do not use `latest` in a release
workflow because the release tool itself is part of the trusted path.
