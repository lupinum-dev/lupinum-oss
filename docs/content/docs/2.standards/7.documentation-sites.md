Every standard library documentation app lives in `docs/`. Use the same folder
as the Vercel Root Directory.

## Choose agent delivery

Use one of these three profiles. Do not claim a request-time feature when the
deployment cannot run it.

| Profile | Human pages | Agent surfaces | Request-time code |
| --- | --- | --- | --- |
| Pure Static | Prerendered HTML | Raw Markdown, `llms.txt`, `llms-full.txt`, sitemap, and metadata | None |
| Static + Provider Routing | Prerendered HTML | Static surfaces plus same-URL Markdown negotiation | A small provider routing function |
| Nitro Runtime | Nitro-rendered HTML | Static surfaces plus negotiation, Markdown recovery responses, link headers, and MCP | Nitro |

Use **Static + Provider Routing** for Lupinum library documentation. It keeps
normal page responses on the provider CDN and runs only the routing layer before
the static asset. Use **Pure Static** when zero request-time execution matters
more than same-URL negotiation. Use **Nitro Runtime** when the application needs
one portable server path instead of provider routing.

Ginko Content and Ginko Docs remain provider-neutral. Follow their versioned
Vercel, Cloudflare, Netlify, or reverse-proxy recipe in the consuming
repository. Do not add provider SDKs or generated provider configuration to the
published content packages.

A provider recipe must parse weighted `Accept` values, exclude non-page paths,
rewrite Markdown-preferring requests to the canonical `/raw/**.md` output, and
preserve the public URL. It must keep a real `404` response for missing pages
and add `Vary: Accept`. Do not rewrite API, asset, raw, LLM, sitemap, robots, or
MCP routes.

## Select the deployment root

Use `docs/` as the Vercel Root Directory for library documentation. Keep
`vercel.json` in `docs/`. Enable source files outside the Root Directory when
the site imports local packages or uses the parent workspace. Build required
local packages before Nuxt builds the documentation app.

A deployed application uses the repository root. Its `vercel.json` also stays
at the repository root.

## Own documentation configuration

The documentation app owns its `package.json`, `nuxt.config.ts`, `site.json`,
`content.config.ts`, and `app/app.config.ts`. It consumes the published Ginko
Content and Ginko Docs packages at exact versions.

Nuxt-branded library sites use the Ginko Docs `nuxt` theme preset. Select it in
`app/app.config.ts` and keep the shared Nuxt palette, surfaces, contrast pairs,
and light/dark behavior in Ginko Docs. A consuming repository owns only
product-specific visual overrides. Do not copy the shared color scale or theme
tokens into each site.

```ts
export default defineAppConfig({
  ginkoDocs: {
    theme: {
      preset: "nuxt",
      codeBlocks: "adaptive",
    },
  },
});
```

Use the `default` preset for products that are not Nuxt-branded or need an
independent visual identity. Add a new preset only when multiple sites need the
same complete visual system; a one-site adjustment stays local.

When a landing hero leads with code, set `layout: "wide"` on its code or
code-tab media. The panel can then use more horizontal space on wide screens.
The text column and smaller layouts stay unchanged.

Deployment configuration belongs to the selected deployment root. A
workspace-backed documentation command can use `pnpm --dir ..` to run the
canonical root build. Do not copy the root build into a second script.

Let Nuxt produce the Vercel Build Output API files in the documentation app.
Do not configure a static output directory.

Delete only generated output before each documentation build. After the build,
verify that every Nuxt asset referenced by generated HTML exists. This check
prevents a stale output folder from producing a green deployment with broken
navigation or search.

## Use canonical product data

Store the final domain, repository URL, Discord URL, product name, and product
description in committed configuration. Use the canonical domain for site,
i18n, canonical, Open Graph, sitemap, and robots configuration.

Add legal notice and privacy links to every site. Use the Lupinum Discord:
`https://discord.gg/RPH6SeA36N`.

## Build local packages first

When docs import a package from the same monorepo, the cold Vercel build must
build that package before Nuxt builds the documentation app. Test this from a
clean checkout. Do not rely on local `dist/` files.

## Keep builds deterministic

Use local fonts. Do not require Google Fonts or another font service during
build. Commit the required font license and provenance.

## Avoid unrelated deployments

Prevent a deployment when the changed files cannot affect the site. This saves
more build time than a small build-speed improvement.

Use Vercel's previous successful deployment SHA. Compare it with `HEAD` across
the complete site dependency boundary. Do not compare only with `HEAD^`, because
one push can contain several commits.

The boundary must include:

- the documentation or application files;
- local packages that the site imports; and
- workspace manifests and the lockfile.

Exclude tests, release automation, and internal files that the site does not
consume.

For a library documentation project, disable automatic Git deployments for
every branch except `main`. Keep `main` enabled so production still updates
after a merge. Add the standard Vercel preview workflow and let a trusted
maintainer comment exactly `/vercel` on a pull request when a preview is useful.
The workflow asks Vercel to build the exact pull-request commit through the
deployment API. GitHub Actions reports the build status and preview URL, but it
never checks out or executes pull-request code while holding the Vercel token.
Do not make a Vercel preview status a required pull-request check.

Give each repository its own dedicated `VERCEL_TOKEN` GitHub secret. Standard
Vercel access tokens can be limited to a team, not to one project, so a token
stored in one repository can still carry authority over other projects in that
team. Use the shortest practical expiry, rotate it, and do not reuse one token
across all libraries. Store `VERCEL_ORG_ID` and `VERCEL_PROJECT_ID` as GitHub
Actions variables. Never commit these values.

Use a fixed Standard build machine and disable on-demand concurrency for
library projects. This is the cost-minimizing library configuration, but it is
not a promise of free builds. Vercel pricing and billing categories change;
verify current pricing and the team's actual usage before making a cost claim.
A preview can wait in the normal queue because queue speed has no business value
for a library documentation site.

Build when the previous production deployment SHA is missing. This fail-open
behavior is safer than skipping a required production deployment.

Check that the previous commit object exists before running `git diff`. A
rebased or force-updated branch can remove that object from Vercel's checkout.
Do not let the resulting fatal Git error fail the deployment.

Keep the configured `ignoreCommand` below Vercel's 256-character schema limit.
Call a committed script when the dependency boundary makes the shell command
too long. Protect the command and both baseline outcomes with a repository
policy check. Review the dependency boundary when the site starts to import a
new local path.

## Verify agent delivery

Test the deployed origin, not only a local Nitro server:

```bash
curl -sSI -H 'Accept: text/html' https://docs.example.com/docs/getting-started
curl -sSI -H 'Accept: text/markdown' https://docs.example.com/docs/getting-started
curl -sSI -H 'Accept: text/html, text/markdown;q=0.5' https://docs.example.com/docs/getting-started
curl -sSI -H 'Accept: text/markdown, text/html;q=0.5' https://docs.example.com/docs/getting-started
curl -sSI -H 'Accept: text/markdown' https://docs.example.com/does-not-exist
```

The HTML-preferred requests must return HTML. The Markdown-preferred requests
must return `text/markdown` with `Vary: Accept`. The missing path must remain
`404` and point agents to `/llms.txt`, `/llms-full.txt`, and the documentation
index. Also request `/raw/**.md`, `/llms.txt`, `/llms-full.txt`, sitemap, robots,
and the MCP server card when the selected profile advertises MCP.
