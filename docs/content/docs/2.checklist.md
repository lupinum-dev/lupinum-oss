A library **follows the Lupinum OSS standard** when every item that applies to
it passes. The audit answers with yes or no and lists the open items by ID,
for example "no; open: NPM-01 (manual), DOC-06 (agent)".

A repository that publishes nothing to npm, such as this one, skips the items
marked *library*.

## How items are checked

- `auto`: the audit checks it every time. Do not record it; run the audit.
- `agent`: an agent checks it with tools or a browser and records the result.
- `manual`: only the maintainer can do it, for example in their npm account.
  Record the date and a short note.

Record `agent` and `manual` results in
[`fleet/libraries.json`](https://github.com/lupinum-dev/lupinum-oss/blob/main/fleet/libraries.json),
next to the repository:

```json
{
  "repository": "lupinum-dev/nuxt-tour",
  "evidence": {
    "NPM-01": "2026-10-03 — 2FA required and tokens disallowed for @lupinum/nuxt-tour",
    "DOC-06": "2026-10-04 — agent solved 5 of 5 tasks from the packaged docs"
  }
}
```

An item without evidence is open. Write evidence only for what was checked;
"we did that once" is not evidence. When an item no longer holds, remove its
evidence.

## Check a repository

From a `lupinum-oss` checkout:

```bash
pnpm audit:repos OWNER/REPO           # every item, with GitHub and npm
node scripts/audit.mjs --local DIR    # file items only, before the first push
```

The audit lists each item with `PASS`, `WARN` or `FAIL`, adds the recorded
evidence for `agent` and `manual` items, and ends with "Follows the standard:
yes" or "no" and the open items. A `WARN` does not count against it; it asks
for a look.

An agent that answers "does this library follow the standard?" runs the
audit and reports yes or no and the open items grouped by who acts:
"I can do now", "needs the maintainer". One line per item ID. It does not
paste the checklist.

## Exceptions

A repository may differ from an item only with a decision line in its
`DECISIONS.md` that names the item ID in parentheses and says why, for example
`D4 (2026-10-01): Keep upstream-drift.yml (FILE-01) — it catches breaking pdfkit releases weekly`.
The audit shows such an item as `PASS` with the reason. Items marked
**no exception** cannot be excepted, because they guard a real attack path.

## Files

Checked by `node scripts/audit.mjs --local DIR` and by `pnpm audit:repos`.

| ID | Item | Check |
| --- | --- | --- |
| FILE-01 | The workflows are `ci.yml`, `release.yml` and `preview.yml` from the starter (*library*), or only `ci.yml`. Another workflow is named in `DECISIONS.md`. | auto |
| FILE-02 | `ci.yml` has a final job named `ci` that needs every check. CI runs lint (including TypeScript), typecheck, test, build and `pnpm audit --audit-level=high`. | auto |
| FILE-03 | Every action is pinned to a full commit SHA. Workflows default to read-only permissions, and no job that can push, open pull requests or start workflows runs repository or dependency code. **No exception.** | auto |
| FILE-04 | *library*: the publish job runs in the `npm` environment with `id-token: write`, publishes the packed tarball with `--provenance --ignore-scripts --access public`, and does not check out, install or run repository code. No npm token anywhere. **No exception.** | auto |
| FILE-05 | *library*: Changesets is configured, `release.yml` runs the Changesets CLI read-only, and `pnpm lint` runs the changeset lint. | auto |
| FILE-06 | `packageManager` pins pnpm 11 or later. `minimumReleaseAge` is at least 1440 with `minimumReleaseAgeStrict: true`; `dangerouslyAllowAllBuilds` is not set. An exclusion is one exact version with a removal date (warns). **No exception.** | auto |
| FILE-07 | `renovate.json` sets `minimumReleaseAge`. There is no `dependabot.yml`. | auto |
| FILE-08 | `README.md`, `LICENSE`, `SECURITY.md`, `CONTRIBUTING.md`, `AGENTS.md`, `CLAUDE.md` and `DECISIONS.md` exist. There is no `MAINTAINING.md` or governance tooling, and the repository stays within the [tooling budget](/docs/adding-tooling#budget) (warns). | auto |
| FILE-09 | `package.json` has the scripts `build`, `lint`, `typecheck`, `test`, `verify` and (*library*) `changeset`. `pnpm verify` runs what CI runs. | auto |
| FILE-10 | The files the standard owns match the starter: `release.yml`, `preview.yml`, `scripts/release.mjs`, `scripts/lint-changesets.mjs` and `scripts/agent-docs.mjs`. The commit an action is pinned to may differ. Fix a bug in these files in the starter first, then copy it. A difference warns unless `DECISIONS.md` names the file. | auto |

## GitHub settings

Checked by `pnpm audit:repos` through `gh api`.

| ID | Item | Check |
| --- | --- | --- |
| GH-01 | The `main` ruleset requires a pull request with resolved review threads, linear history and squash merges, blocks force pushes and deletion, and requires the check `ci` from GitHub Actions. It has no bypass actors. **No exception.** | auto |
| GH-02 | *library*: a tag ruleset blocks moving and deleting every tag prefix `release.yml` creates, with no bypass actors. **No exception.** | auto |
| GH-03 | Merges are squash only, branches are deleted after merge, and auto-merge is off. | auto |
| GH-04 | The Actions token is read-only by default. *library*: Actions may create pull requests. | auto |
| GH-05 | *library*: the `npm` environment has a required reviewer, administrators cannot bypass it, and only `main` can deploy. **No exception.** | auto |
| GH-06 | Secret scanning with push protection, private vulnerability reporting, Dependabot alerts and CodeQL default setup are on. Dependabot security updates are off. | auto |
| GH-07 | The repository has no Actions secrets. | auto |
| GH-08 | Renovate runs: its Dependency Dashboard issue is open and was updated in the last 14 days. | auto |

## npm

*library* only. Checked by `pnpm audit:repos` against GitHub and the npm registry.

| ID | Item | Check |
| --- | --- | --- |
| NPM-01 | Every package requires two-factor authentication and disallows tokens under **Publishing access**. | manual |
| NPM-02 | The versions on `latest` and `next` carry npm provenance, which proves the trusted publisher for `release.yml` works. Only a package's first version, published by hand, may lack it (warns); any other version without provenance fails. | auto |
| NPM-03 | The newest published version of every package has its Git tag and GitHub release. | auto |
| NPM-04 | Nothing waits too long: no Version packages pull request older than 14 days, and `next` is not behind `latest` (warns). | auto |

## Docs

| ID | Item | Check |
| --- | --- | --- |
| DOC-01 | The docs site answers on the `homepage` domain from `package.json`, deployed by Vercel's Git integration. | auto |
| DOC-02 | `/llms.txt` lists the pages, and the agent Markdown contains no placeholder for a live example or component. | auto |
| DOC-03 | *library*: every public package exports `./agent-docs`, ships it through `files`, and its own README has the **Agent setup** section. | auto |
| DOC-04 | *library*: the pages follow the structure on [Write library docs](/docs/writing-docs): Start, Guides, Reference, Help. | agent |
| DOC-05 | *library*: every public export, prop and option has a doc comment with its meaning and default. Every error a user can hit names the fix. | agent |
| DOC-06 | *library*: an agent solved at least five typical tasks using only the packaged docs, and the result is recorded. | agent |

## Maintenance

Checked by `pnpm audit:repos`.

| ID | Item | Check |
| --- | --- | --- |
| OPS-01 | The repository is listed in `fleet/libraries.json`. | auto |
| OPS-02 | The last `ci` run on `main` succeeded. | auto |
| OPS-03 | No open Dependabot alert of high or critical severity. | auto |
| OPS-04 | No branch other than `main` is older than 30 days without an open pull request (warns). | auto |
| OPS-05 | No open pull request is older than 14 days without activity (warns). | auto |
