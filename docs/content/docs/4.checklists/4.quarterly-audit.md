---
title: Quarterly audit checklist
description: Check repository files and external controls before they drift.
icon: lucide:calendar-check
---

Run this audit every quarter and before a major release.

## Source control

- [ ] Local instructions match the current architecture and commands.
- [ ] No obsolete migration, compatibility path, package name, or domain remains.
- [ ] Required workflows use valid full action SHAs and minimum permissions.
- [ ] Checkout does not persist credentials.
- [ ] Issue forms, PR template, security path, and CodeRabbit still work.

## Dependencies and supply chain

- [ ] The 24-hour quarantine is explicit.
- [ ] Every quarantine exception is exact, justified, and not expired.
- [ ] Renovate is active and security alerts are reviewed.
- [ ] Full and production audits pass.
- [ ] Changelogen and the package manager are pinned as required.

## npm and releases

- [ ] Each repository still matches its single-package, fixed-version, or
  independent-family release profile.
- [ ] Every public package has the expected dist-tags and provenance on recent releases.
- [ ] Every trust record targets the current repository, maintained workflow file, and `npm`.
- [ ] Every public package requires 2FA and disallows bypass tokens for publishing.
- [ ] The `npm` environment still requires review and only permits `main`.
- [ ] No npm token or duplicate publication path exists.
- [ ] Git tags, GitHub releases, changelog versions, and npm versions agree.
- [ ] Version candidates start from reviewed version pull requests.
- [ ] Preflight uses successful exact-SHA `main` CI and accepts at most the reviewed version.
- [ ] No-op preflight finishes before the protected `npm` environment.
- [ ] The pre-approval summary identifies the source, CI run, channel, package set, and tarball digests.
- [ ] Automatic Reconciliation, when used, finds one unique incomplete candidate.
- [ ] Every retry reuses the retained candidate and never rebuilds it.

Record immutable releases created before the fleet enforcement cutoff as
`HUMAN-ONLY`; do not retroactively call them `PROVEN`. Current releases must
satisfy the Core. A historical prerelease can remain on npm's automatic
`latest` before the first stable version; require the current prerelease on
`next` and do not mutate immutable history automatically.

## Production documentation

- [ ] Vercel uses the Root Directory required by the repository profile and the canonical domain points to production.
- [ ] A clean deployment succeeds.
- [ ] The Vercel ignore command still covers every site dependency and skips unrelated changes.
- [ ] The library preview workflow matches the current Lupinum OSS standard.
- [ ] Library previews remain optional, exact-SHA, and on demand.
- [ ] Dedicated token and variable names exist; token scope and expiry are recorded accurately.
- [ ] Build usage, current pricing, fixed Standard selection, and disabled
  on-demand concurrency match current needs.
- [ ] If analytics is enabled, the Plausible script ID matches the current site.
- [ ] If analytics is enabled, `docs-feedback` events arrive.
- [ ] The production acceptance checklist passes.

Record each failure as a focused issue with an owner and deadline. Do not create
a broad cleanup branch that mixes unrelated repositories.
