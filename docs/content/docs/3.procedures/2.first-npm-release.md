---
title: First npm release
description: Bootstrap a new package once, then bind all later releases to trusted publishing.
icon: lucide:package-plus
---

npm cannot configure a trusted publisher for a package that does not exist.
Staged publishing also cannot create a new package. The first publication is a
controlled, interactive bootstrap.

## Certify the first tarball

Merge the release candidate to protected `main`. Download the retained
release-candidate artifact from the successful main CI run at that exact
commit. Do not dispatch `publish.yml` before npm trust is ready.

Verify the artifact digest and the release manifest. Do not run `npm pack`
again. Do not rebuild the package locally.

## Publish the exact tarball

Sign in to npm with the owning human account and two-factor authentication.
Publish only the certified file:

```bash
npm publish ./certified-package.tgz \
  --access public \
  --tag latest \
  --ignore-scripts
```

Use `--tag next` when the first version is a prerelease.

Compare the registry's version, dist-tag, and `dist.shasum` with the certified
manifest. Stop if any value differs.

## Configure the trusted publisher

Bind the published package to the exact repository, workflow file, and
environment:

```bash
npm trust github @lupinum/package-name \
  --repo lupinum-dev/repository-name \
  --file publish.yml \
  --env npm \
  --allow-publish \
  --yes
```

List the trust record and confirm the repository, `publish.yml`, `npm`
environment, and publish permission. Repeat this step for every independently
published package in a monorepo.

## Complete the protected workflow

After every package has its trusted publisher, dispatch `publish.yml` with the
same version. The workflow compares npm with the certified SHA-1 and skips the
existing package. It then verifies the dist-tag and creates the GitHub tag and
release from the certified changelog section. Do not create them manually.

Install the public package in a clean consumer.

The bootstrap version does not have GitHub OIDC provenance. Record this known
limitation. Every later version must use the normal trusted workflow.
