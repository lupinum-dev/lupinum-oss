Most supply-chain attacks on npm are caught and pulled within hours. We do not
install a version until it is a day old, we do not run install scripts we did
not approve, and publishing never runs dependency code. All of this is built
into pnpm and Renovate; there are no custom dependency scripts.

## Quarantine

`pnpm-workspace.yaml`:

```yaml
minimumReleaseAge: 1440 # minutes: new versions wait 24 hours
allowBuilds:            # the only dependencies allowed to run install scripts
  esbuild: true
```

pnpm refuses to resolve a version younger than 24 hours, including transitive
ones. Only list packages in `allowBuilds` (`onlyBuiltDependencies` on pnpm 10)
that really need a build step. Never set `dangerouslyAllowAllBuilds`.

Pin pnpm in `package.json` (`"packageManager": "pnpm@11.x.y"`). An older pnpm
can silently ignore these settings.

The quarantine applies to third-party versions only. Our own fixes release
immediately.

## Updates

Renovate opens update pull requests. `renovate.json`:

```json
{
  "extends": ["config:recommended", "helpers:pinGitHubActionDigests"],
  "minimumReleaseAge": "1 day",
  "internalChecksFilter": "strict",
  "rangeStrategy": "replace",
  "schedule": ["before 6am on Monday"]
}
```

Renovate waits the same day before it proposes a version, and keeps GitHub
Actions pinned to full commit SHAs with a version comment. `replace` keeps the
ranges that consumers of a library see; a repository that publishes nothing
may use `pin`. The weekly schedule batches updates into one review session.
Renovate opens security updates outside the schedule; pnpm still makes the
new version wait 24 hours unless you exclude it (see the last section). Dependabot stays on
for security alerts only; do not let both bots open update pull requests.

An agent may merge a green Renovate pull request for a patch or minor update.
A major update, or an update to anything that runs in CI or at build time
(bundlers, test runners, GitHub Actions), gets a quick read of the release
notes first.

## Audit

CI runs `pnpm audit --audit-level=high` as part of `pnpm verify`. It fails on
high and critical advisories anywhere in the workspace, so a low-severity
advisory deep in the docs site does not block every pull request and release.
Renovate and Dependabot alerts show the rest. When the audit fails:

1. Update the affected package, usually through the open Renovate pull request.
2. If no fixed version exists, check whether the vulnerable code is reachable.
   If it is not, ignore that one advisory with a reason and a date to look again:

   ```yaml
   # pnpm-workspace.yaml
   auditConfig:
     ignoreGhsas:
       - GHSA-xxxx-xxxx-xxxx # dev-only, not reachable; recheck 2026-11-01
   ```
3. If it is reachable in published code, treat it as a
   [security report](/docs/security).

## When the quarantine blocks something you need now

First try an older version that has the fix. If that is not possible, for an
urgent security fix only, exclude one exact version:

```yaml
minimumReleaseAgeExclude:
  - some-package@1.2.3 # urgent fix for GHSA-…; remove after 2026-10-02
```

Remove the line once the version is a day old. The audit reports every
exclusion as a warning until you do. Never exclude a range or a whole package.
